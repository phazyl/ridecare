Test traffic ideas for Greater Malé before spending on AI and hardware

An interactive model of Malé and Hulhumalé built on the real street network and the IUM vehicle-restriction report. It runs in any web browser, needs no installation, and is open to inspect.

What it is

A simulation of the streets of Malé, Hulhumalé and the roads that join them. It uses the street network from OpenStreetMap and the vehicle figures from the IUM report “Assessment to Determine Vehicle Restrictions in the Greater Malé Region” (March 2025, PDF). Every vehicle is an individual, from motorcycles to lorries, and vehicles can never overlap. Streets, widths, one-way rules and names come from the map data.

Villimalé is not in the current network file, so it does not appear on the map.

What it shows

  • The fleet by year. The 2021 to 2026 fleet by vehicle type (128,779 vehicles in 2026), with every figure marked as reported, trend-based or estimated.
  • Time of day. Choose a year, a day of the week and a time. By default it follows the current Maldives time. About 11% of the fleet is on the move in a peak hour, per the report, and the rest is parked. The model shows where those parked vehicles stand along the kerbs.
  • Space limits. How much road and kerb the fleet needs. The Placement report lists exactly which vehicle types do not fit, by area, and how much kerb re-opening would recover.
  • Safe following distance. An optional setting adds reaction and braking distance for moving vehicles, so you can see how speed reduces road capacity.
  • Hotspots. The streets where queues form in the model, with rule-based suggestions.

What officers can try

  • Make a street one-way, in either direction, or two-way. Vehicles on it turn to the new direction.
  • Close a street to all traffic, for example for works or an event. Vehicles route around it.
  • Ban parking on one or both kerbs of any street, or apply a rule to every street at once. By default each street allows parking on one kerb only, and the bridge road allows none.
  • Compare measures side by side: plate rotation, limiting goods vehicles to off-peak hours, the report’s proposed fleet cuts, and clearing kerbside parking.

Everything updates live. Street settings are remembered in the visitor’s own browser.

What kind of model it is

It is a stochastic, agent-based microsimulation. Each vehicle is a separate rectangle that moves along the street network in small time steps and only moves into free space. Moving vehicles follow the Intelligent Driver Model (IDM), a standard car-following model: each one accelerates and brakes gradually according to the gap and relative speed of the vehicle ahead, with starting parameters set by vehicle size class and a random driver temperament for each vehicle. Randomness enters through starting positions, lane choice, the turn taken at each junction and the collision events. It is not a full Monte Carlo study: each scenario is run once, so small differences between measures are treated as noise. Repeating each scenario with many random seeds and reporting ranges is a planned improvement.

What it is good for

  • Screening ideas cheaply before any road work or procurement.
  • Explaining the case for a measure to the public and to decision-makers.
  • Showing which streets and vehicle types create the most pressure on space.
  • Setting up the scenarios that an AI system would later need to be tested against.
What it does not do yet. This is a prototype, not a forecast.
  • Vehicles follow random routes. There are no real origins and destinations.
  • There are no traffic signals and no pedestrians. Each vehicle type has its own desired speed, and the IDM parameters (acceleration, braking, time gap) are literature starting values that have not been calibrated to Maldives traffic.
  • Nothing is calibrated against measured traffic counts or speeds.
  • The shape of the daily traffic curve between the report’s peak windows is an assumption. The report gives no weekend breakdown, so Friday and Saturday curves are assumed, with the same daily volume as a weekday.
  • Parking is modelled along street kerbs, one vehicle deep: motorcycles end-on (1 m of kerb each, as in HDC’s bay standard), everything else lengthwise. The report’s 132,230 motorcycle and 7,163 car slots were surveyed along the streets and are used as bay limits, with car-size bays shared by cars, pickups, vans and larger vehicles. OpenStreetMap maps only about six off-street lots (around 1,100 spaces). Private and residential garages cannot be estimated, because HDC declined to share the data; they are a user setting that starts at zero.

Accident and collision estimates

The simulation does not produce collisions from its physics. Vehicles never overlap, so none occur. The collision figures are a separate statistical estimate built from Maldives Police Service accident counts, and the red flashes on the map are random draws at that rate.

How the estimate works.

  • Start from the police-reported accident count for a year. We assume 80% of those are in Greater Malé. This share is an assumption and is not verified against the police data.
  • Scale it with the fleet size using a simple power law, where β is the elasticity (how strongly accidents grow with the number of vehicles):
accidents(year) = accidents(2024) × (fleet(year) ÷ fleet(2024)) ^ β
  • β defaults to 1.5, with 1.0 (accidents grow in proportion to fleet) and 2.0 (they grow faster) shown as a band.
  • When the time-of-day clock is on, the rate rises and falls with the number of vehicles moving, so peak hours show more events than the night. The annual total is unchanged.

How to read the projection. The estimate is anchored to 2024, so it is closest there. For earlier years it runs above the recorded counts, which shows that accidents rose faster than the fleet did over 2021 to 2024. That is partly because reporting practice changed, traffic recovered after COVID, and Hulhumalé grew. The power-law elasticity is a modelling choice, not a measured causal effect. Use the estimate to compare scenarios (for example, what a 20% smaller fleet might mean), not to forecast an exact number of accidents.

Proposed next step

Calibrate the model with real data: vehicle counts from existing cameras, a few days of measured speeds, and origin–destination patterns. A calibrated model could then be used to test an AI system’s decisions safely before it touches real roads. The simulation also shows which data and which cameras are worth buying, so that spending can be targeted.

Sources: IUM report (March 2025, PDF); OpenStreetMap contributors (ODbL); National Bureau of Statistics vehicle registrations; Maldives Police Service accident counts via MV+. This is a demonstration model and not a calibrated traffic forecast.
